# Waivers for verify_hygiene.py.
#
# An entry says: this rule fired on this exact line, a human looked at it, and
# the line is right. Nothing else. It is not a way to turn a rule off for a
# file, and there is deliberately no syntax for that.
#
# Format - three parts, blank line between records:
#
#     [RULE-ID] repo/relative/path.ext
#     reason: why THIS line is correct. Continuation lines are indented.
#     line: the exact text of the line, stripped of leading whitespace
#
# The `line:` anchor is the whole design. Edit that line and this waiver stops
# matching, the rule fires again, and somebody re-decides against the new text.
# A waiver that matches nothing is reported as a FAILURE, not ignored, because
# that is the only force that ever makes this file shorter. If you see that
# failure, the answer is usually to delete the record.
#
# Line numbers are deliberately absent. An anchor on file:line moves the moment
# anything is inserted above it, and then it either blocks a clean commit or
# silently excuses whatever slid into that slot.
